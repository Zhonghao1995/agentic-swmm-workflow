# Tool notes

Short, hand-reviewed notes about how to call one tool, learned from runs. When the tool registry is built, each tool's notes are appended to that tool's description, so I read them at the moment I consider the tool, in every session, without spending the startup memory budget.

One `## <tool>` section per tool, at most three bullets of two hundred characters each. Nothing here is written by the program: a note arrives through a promoted proposal (`aiswmm memory promote <id>`, kind `tool`) or a pull request, and leaves the same way.
